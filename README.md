# Codex Handoff

Codex Handoff 是一个面向 Windows 的 Codex 离线搬家工具。它可以把一个 Codex 任务及其项目文件导出成单个 `.codexhandoff` 文件，然后在另一台电脑或另一个 Codex 账号中恢复为可继续工作的任务。

> 本仓库只用于公开发布安装包、自动更新元数据和使用说明，不包含应用源码，也不会保存用户的聊天或项目数据。

## 下载

请前往 [Releases](https://github.com/Saury12138/codex-handoff-releases/releases) 下载最新的 Windows 安装包：

- 文件名格式：`Codex-Handoff-Setup-x.x.x.exe`
- 支持系统：Windows 10 / Windows 11（64 位）
- 使用前请先安装并登录 Codex 桌面应用

如果已经安装 Codex Handoff，也可以在软件右上角点击 **检查更新**。

## 主要功能

- 完全离线迁移聊天和项目，不需要 GitHub 仓库或同步密钥。
- 单文件导出，方便通过 U 盘或可信的局域网工具传输。
- 根据本机 Codex 任务记录自动识别项目文件夹，同时保留手动选择。
- 支持把 `.codexhandoff` 文件直接拖到导入区域。
- 可在目标电脑当前登录的 Codex 账号中创建新任务，支持跨账号复制。
- 恢复后的新任务会在首条消息中按“用户 / Codex”顺序显示完整文字上文，可直接查看并继续工作。
- 导入前检查搬家包完整性，发现损坏或修改会停止导入。
- 项目始终恢复到新目录，不覆盖已有项目。
- 启动时自动检查新版，也可以随时手动检查更新。

## 使用方法

### 一、在原电脑导出

1. 打开 Codex Handoff。
2. 从自动识别的项目列表中选择项目；没有显示时点击 **手动选择**。
3. 选择需要迁移的 Codex 任务；需要时可点击 **刷新任务**。
4. 根据需要勾选 **同时携带项目文件**。
5. 点击 **导出 .codexhandoff 文件** 并选择保存位置。
6. 使用 U 盘或可信的局域网传输工具，把文件复制到目标电脑。

### 二、在目标电脑导入

1. 先在 Codex 中登录准备接收任务的账号。
2. 打开 Codex Handoff。
3. 点击 **选择 .codexhandoff 文件**，或把一个搬家文件直接拖到导入区域。
4. 确认任务名称、对话轮次和项目文件信息。
5. 点击 **导入为当前账号的新任务**。
6. 选择项目保存位置，等待程序恢复项目和聊天。
7. 回到 Codex 的任务列表继续工作。

导入属于“复制”：原电脑和原账号中的任务不会被移动或删除。

项目自动识别只读取本机 Codex 任务记录中保存的工作目录，不会遍历或扫描整块硬盘。已经删除或移动的目录会被自动忽略。

恢复后的聊天会把原任务中的用户消息和 Codex 回复集中显示在首条“已恢复的聊天上文”消息中。由于 Codex 当前不允许第三方程序创建伪造的原生历史轮次，这些内容不会拆成原来的多个气泡，但顺序、角色和文字内容都会保留，模型也会把它们作为继续工作的上文。

## 项目文件规则

勾选“同时携带项目文件”时，程序会自动排除不适合搬家的内容，包括：

- `.git` 版本历史
- `node_modules`、虚拟环境等依赖目录
- 构建产物与缓存
- `.env` 文件
- 私钥和证书文件
- Codex 登录信息与内部数据库

单个离线包携带的项目文件默认上限为 256 MB。大于限制时，可以取消携带项目文件，改用其他方式复制项目。

## 自动更新

- 软件启动后会安静地检查新版本。
- 没有更新时不会弹窗打扰。
- 有更新时会显示版本号，并询问是否自动更新。
- 选择 **是**：自动下载、退出并安装新版本。
- 选择 **否**：启动时 7 天内不再提醒。
- 即使处于 7 天暂停期，也可以点击右上角的 **检查更新** 主动检查。

自动更新只会访问本公开仓库的 Release 文件，不会上传聊天、项目文件或使用记录。

## 安全提示

`.codexhandoff` 文件没有密码保护，其中可能包含聊天和源代码。请像保护项目源代码一样保管它：

- 只通过 U 盘或可信的局域网工具传输。
- 不要上传到公开网盘、公开仓库或聊天群。
- 完成迁移后，可按需删除搬家文件。
- 不要把账号令牌、Cookie 或私钥手动放进项目目录。

## 常见问题

### 为什么刷新后看不到任务？

确认 Codex 已安装并登录，目标任务已经结束当前回复，然后重新选择项目目录并刷新任务。

### 导入后为什么出现一个新任务？

Codex Handoff 会在目标电脑当前登录的账号下创建新任务，并把原对话显示为一条完整的可见上文。它不会修改原任务的所有权。

### 为什么历史聊天集中显示在一条消息里？

Codex App Server 目前只允许第三方程序创建新的真实轮次，不能把外部记录写成多条原生历史气泡。Codex Handoff 因此按原顺序标注“用户 / Codex”，集中显示全部文字上文，同时避免重新执行历史命令和工具调用。

### 会覆盖目标电脑上的项目吗？

不会。携带项目文件时，程序会创建名称类似 `项目名-restored` 的新目录；如果名称已存在，会自动选择新的编号。

### 工具调用和命令会重新执行吗？

不会。历史工具调用会保留在搬家快照中，但导入时不会重新执行，以避免重复修改文件或产生其他副作用。

### 导入后的任务为什么显示为只读？

v0.10.0 的恢复确认轮次错误地把 `read-only` 保存成了后续轮次的默认权限。该问题已在 v0.10.1 修复：恢复后的任务默认使用 `workspace-write`，只允许写入恢复后的项目目录，其他系统路径保持只读，越界操作仍需用户批准。请升级到 v0.10.1 或更高版本后重新导入；已经导入的旧任务也可以先在 Codex 的任务权限设置中改为 **workspace-write**。

## 隐私说明

任务导出、项目打包和任务恢复都在本机完成。除了检查和下载软件更新，Codex Handoff 不会主动连接本仓库，也不会把搬家内容上传到 GitHub。
